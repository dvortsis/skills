# Document Builder

You write `doc.json`; the scripts build the .docx and PDF and check them. Never hand-build Word XML, never edit the outputs or `assets/`. Run the scripts with `python3` (or `python` where that is the command, as on Windows).

## 0. Preflight (first, before any other work)
Run `scripts/preflight.py` from this skill's folder (the folder containing this SKILL.md). On `READY`, continue. If it fails or is missing, stop and say once: "The document-builder skill loaded without its supporting files. Please attach `document-builder.zip` in this chat." Then unzip it and rerun the preflight.

## 1. Brand
The brand comes from where `doc.json` lives, so keep `doc.json` and the outputs in the user's project (or a folder inside it), never in this skill's folder, and call the scripts by their full path in this skill's folder (`python3 <skill folder>/scripts/build_doc.py ...`; the commands below are written relative to it). If `doc.json` must live elsewhere, pass `--brand`, set `meta.brand`, or set the `BRAND_PROJECT` environment variable to the project root. Run `python3 scripts/brand.py show --source doc.json` (before doc.json exists, `--project <project folder>`). Put its first line (`BRAND: ...`) in your reply. If it says `neutral defaults`, ask once whether the user has a logo, brand colors or a `brand.json`, then continue either way: the document builds in the neutral theme with no logo and no copyright line. The brand lookup order is `--brand`, `meta.brand` in doc.json, a `brand.json` beside doc.json or at the project root, then the project's own files (design tokens, Tailwind or CSS theme variables, Office themes, a logo file, the LICENSE owner). Fonts follow the same rule and are never hard-coded: the project's fonts (named in its theme files or brand.json, or font files it ships), else the bundled Inter (body and headings) and JetBrains Mono (code); the build measures and spaces text with the real font files and embeds them in the .docx, so the document looks the same where the font isn't installed. The build prints a `FONTS:` line saying where each font came from. To pin or correct it, write a profile with `python3 scripts/brand.py detect --out brand.json`, edit the name, org, footer, logo, colors (by role: primary, dark, secondary, alert, text, ...) or `terminology` (house terms), and check it with `python3 scripts/brand.py check brand.json`.

## Workflow
1. **Frame.** Get the audience, purpose, owner, version, date and `doc_type` (`user-guide`, `technical-reference`, `sop`, `manual`, `report`, `policy`; or a sheet, below). Ask once in a single line for anything you can't infer or find with connected search tools (if any) or the sources the user names.
2. **Gather facts.** Read the sources once and note each fact with its source in `meta.sources`. Facts come only from the request, attachments, connected search tools (if any) or the sources the user names; unknowns become open questions, never placeholders.
3. **Outline first.** Write the section titles (task-based, three levels at most) and check them against the required sections for the type in `references/doc-schema.md`. Read `references/technical-writing.md`.
4. **Write `doc.json`.** For a user guide for business users, copy `assets/user-guide.example.doc.json` (lean profile, the default: numbered task topics, a Reference chapter, contents and glossary; no objectives or takeaways boxes, no index). For a textbook-style guide or manual, set `meta.profile: "textbook"` and copy `assets/textbook.example.doc.json` (chapter openers, `objectives` and `takeaways` boxes, worked examples, task finder, answers appendix, index). Other types copy `assets/user-guide.example.doc.json`. Replace every value, and pick the block that fits each piece of content: `procedure` for tasks, `table` for comparisons and reference values, `figure` for screenshots, `callout` for notes, tips and warnings, `code` for exact text to type.
5. **Screenshots.** Only captures the user supplies, with no PHI or PII, saved next to doc.json, or, when no capture exists, a source-gated, stamped screen illustration supplied by an overlay skill (drawn from a layout spec, every label traced word for word to a saved source, stamped "Illustration, not a live screenshot"); caption it as an illustration (ILLUSTRATION_LABEL) and list it as pending in the shot list. If any are missing, ask once for the named files and build with `--draft`. A user guide with three or more procedures that quote UI labels needs figures, or `meta.shotlist` pointing to a shot list (FIGURE_NONE); then report the screenshots as pending, never the document as complete.
6. **Build.** `python3 scripts/build_doc.py doc.json --out <Name>.docx --pdf [--draft] [--brand brand.json]`. It prints the BRAND line, runs the gate first and refuses to build on any FAIL. The PDF comes from LibreOffice, or from Microsoft Word on Windows when LibreOffice is missing. If it prints `PDF NOT RUN`, deliver the .docx and say the PDF wasn't made.
7. **Lint.** `python3 scripts/lint_doc.py doc.json --docx <Name>.docx --pdf <Name>.pdf [--draft] [--brand brand.json]`. Fix doc.json and rebuild until 0 failed. `WARN [LOGO_NONE]` means the project has no logo, so the cover has none; mention it once. `WARN [FONT_MISSING]` means the project names a font whose files aren't available, so it couldn't be embedded; ask once for the font files (or a brand.json `font_files` entry).
8. **Look.** The PDF checks catch split callouts (CALLOUT_SPLIT), words broken in table cells (WORD_BREAK) and mid-chapter pages that end above 45% (PAGE_FILL, warn; a short last page of a chapter is fine when chapters start on a new page) and figure text under 7 pt at print size (FIG_TEXT_SIZE, warn: crop or split the figure). Then review by contact sheet: `python3 scripts/visual_batch.py render <file>.pdf` (sheets of 4 in a new folder), view every sheet, open a page full size only where its sheet shows a possible problem or it has small text (`viewed`, `full`, `finding`, `fixed`), and run `visual_batch.py check <render dir>` until VISUAL_BATCH passes; reply "visual review: N pages on S sheets, F viewed full size, M findings fixed". If preflight printed `WARN render: not available` or you can't view images, skip this loop and report "visual review: not run (reason)".
9. **Deliver.** Save the .docx and .pdf to the output folder and link both. Add in at most 6 lines: the BRAND line, the outline, open items, and the checks line (`LINT: n checks, 0 failed`, PDF made or not, "visual check: N pages inspected, M fixed" or not run).

## Sheets (quick starts, job aids, one-pagers)
For one page per role or topic, set `meta.layout: "sheet"` and a kebab-case `doc_type` (`quick-start`, `job-aid`, `checklist`, ...). Copy `assets/quick-start.example.doc.json`: two roles, each within the format's word limit from the catalog (Quick Start: 250 per role), each with the six Quick Start subsections in order (Who It's For, What You Can Do, Steps, Worked Example, Common Mistakes, Get Help), a `step_diagram` (3-6 steps, labels of 4 words or fewer) above 3-5 numbered steps, a `card` for the worked example, and `"width": "half"` pairs side by side. No cover, contents or appendices; each top-level section starts a page with the brand's dark title band (and the logo, when the brand has one). Build and lint as above: lint must show `QS_PAGE_COUNT pass` (quick-start) or `SHEET_PAGE_FIT pass` and 0 failed. If a section runs over a page, cut words; the build never shrinks text below 9 pt body / 8 pt tables and figures. Rules: `references/doc-schema.md` (Sheet layout).

## Revisions
Targeted edits to doc.json, add a `revisions` entry, bump `meta.version`, rebuild, re-lint, re-deliver as `<Name>_v2`. Keep doc.json next to the outputs.

## Never
Invented facts, steps or screens; placeholder text; unsourced or unstamped screen drawings presented as screenshots; PHI; filler words; headings deeper than 1.1.1; procedures longer than 12 steps; tables wider than 6 columns; icons outside the Tabler set; colors outside the project brand palette; fonts other than the brand's; a logo the project doesn't have (no logo is drawn rather than a stand-in); hand-edited outputs.
